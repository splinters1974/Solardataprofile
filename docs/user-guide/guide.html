If you only read one page

Read section 1. Then, before you send anything to a client, check two things on every site: the building type and opening hours are right, and the data quality verdict isn't Poor. Most wrong answers come from one of those two.

1. Quick start

  1. Open the app. Double-click Ameresco-Data-Analyser.html. It opens in Chrome or Edge. Nothing installs and nothing goes online.
  2. Load the meter files. Drag them onto the upload box, or click it to browse. Use one file per meter; each file becomes a site. Try the five sample files in the folder first.
  3. Set building type and hours. Every site starts as Office / commercial (07:00 to 19:00 weekdays). For several sites of the same kind, use Set building type and opening hours for all sites at once above the summary tiles. Then open any site that differs and correct it.
  4. Check the rate. The default is 25p/kWh fully delivered. Change it at the top of the page, or override it on any one site.
  5. Read the results. The Where to start table ranks sites by what out-of-hours use above base load costs a year. Click a site for its findings, data quality, headroom and charts.
  6. Export. On a site: Site summary (PDF), Download all charts (PDF) or Charts as separate PDFs (zip). On the main page: Portfolio report (PDF), Export to Excel and Table to Excel. Add the client's name and logo first so they print on every page.
Before anything goes to a client
  • Building type and hours are right for every site. Wrong hours make the out-of-hours figures wrong.
  • The data quality verdict is Good or Check, and you've read any Check items. Don't quote figures from a Poor file.
  • The site has close to a year of data. Under 330 days, the annual figures are scaled up from part of the year.
  • Costs are described as what a pattern costs now, not a saving. The PDFs already say this; keep your covering email consistent.

2. What the tool is, and what it isn't

The Data Analyser turns half-hourly (HH) electricity data into a ranked view of where a site or estate wastes energy, priced at a unit rate, plus a check on how much spare supply capacity there is for electrification. It handles a single site or a portfolio of hundreds, and produces Ameresco-branded PDFs and spreadsheets.

It is

  • A screening tool. It tells you where to look and roughly what's at stake, quickly enough to use in a first meeting or a bid.
  • Offline and private. Everything runs in your browser. Files are read on your laptop and never uploaded anywhere. You can use it with no internet connection.
  • Consistent. The same file gives the same answer for everyone, with the method written down (section 13).

It isn't

  • An audit or a savings guarantee. A cost figure is what a pattern costs at the rate entered. How much of it can be removed is an engineering judgement made on site.
  • A connection study. Headroom is worked out from the peak in the data supplied. A colder winter, a fault, or load not on that meter moves the answer. Treat it as a screen before talking to the DNO, not instead of it.
  • A bill validation tool. It uses one fully delivered rate. It doesn't model time-of-use tariffs, capacity charges, DUoS bands or the Climate Change Levy separately.
  • Gas or heat. It reads electricity HH data in kWh. Other half-hourly kWh data will load, but the findings are written for electricity.

Where the data goes

Nowhere. Closing the browser tab clears it. Clear all data (top right) takes the app back to empty without closing it. A file you export (PDF, Excel, customer edition) is saved to your Downloads folder like any other download, so look after it in line with the client's data agreement.

4. Loading meter data

Files it reads

  • File types: .xlsx, .xlsm, .xls, .csv and .txt. CSVs can be comma, semicolon or tab separated; the app works out which.
  • One meter per file. Each file is one site. Name the file after the site; the file name becomes the site name (you can change it).
  • Workbooks with several sheets: the app picks the sheet that looks most like HH data.

Layouts

LayoutLooks likeNotes
Days down the side (most common)One row per day: a date, then 48 half-hourly readings (00:00 to 23:30).Meter ID or MPAN columns before the date are ignored.
Days across the topOne column per day, 48 rows of readings down the side.Detected automatically and turned round.
50-period exportsA date, then 50 columns (the two extra are the clock-change periods).The first 48 are used, with a note.

What it sorts out for you

  • Title rows above the data (site name, meter number, report dates): up to 8 are skipped.
  • Dates are read day first (UK), including Excel dates, text dates and two-digit years. Rows are put in date order.
  • No date column: the data is assumed to start on 1 January, with a note. Day-of-week and bank holiday analysis will then be off, so add dates if you can.
  • Rows with no date below the data (template padding) are ignored.
  • A repeated date keeps the first row, with a note. See below for when it refuses instead.
  • Text in a reading cell (an error code, say) counts as 0, with a count in the notes.
  • Blank readings, such as the rest of a part-recorded last day, are kept and count as no use in the totals. They're left out of base load, the lowest reading and the load duration curve, so they can't drag those to zero. A dated row with no readings at all is treated as a missing day.

What it refuses

A file with several meters stacked one after another, which is common in supplier portal exports, shows up as many repeated dates. The app refuses it with a message, rather than splicing different meters into one profile. Split it into one file per MPAN and load those.

Data notes

Anything the app had to fix or assume is listed in an amber box at the top of the site page, and the site shows has data notes in the table. Read them. They're also the first thing to check if a number looks wrong.

5. Setting up sites

Building type and opening hours

Opening hours drive every out-of-hours figure, so this is the most important setting. Choosing a building type fills in typical hours, which you then adjust to match the site.

TypeDefault hours
Office / commercial07:00 to 19:00 weekdays. Closed weekends and bank holidays.
School / education07:00 to 17:30 weekdays. School holidays count as out of hours, which is usually right: the building should be near base load then.
Hospital / 24-7 estateOpen around the clock, so there's no out-of-hours analysis. Base load, peak and headroom still apply.
Leisure centre06:00 to 22:30 weekdays, 07:00 to 20:00 weekends.
Retail07:30 to 20:30 Monday to Saturday, 09:30 to 16:30 Sunday.
Industrial (two shift)06:00 to 22:00 weekdays.
Custom hoursSet your own.

Treat bank holidays like Sunday is on by default: a bank holiday uses Sunday's hours. Turn it off for sites that work bank holidays. England and Wales bank holidays are built in, including the moved ones (2012, 2020, 2022). Scottish and Northern Irish holidays aren't, so treat those as normal days or adjust the hours.

All sites at once

The bulk setting replaces each site's type and hours. It doesn't touch names, rates or capacity.

Unit rate

A fully delivered rate in p/kWh (energy, network, levies and VAT if the client pays it). The default is 25p and applies to every site; set it at the top of the main page. To give one site a different rate, type it on that site; the box goes from grey to black. Back to the portfolio default undoes it.

Supply capacity and power factor

Enter the agreed supply capacity in kVA (from the bill or supply agreement) to switch on the headroom check (section 9). Power factor converts metered kW to kVA. Use 0.95 if you don't know it; if the bill shows reactive power charges, the real figure is probably lower, and headroom will be smaller than shown.

6. The portfolio view

The main page shows totals for every site loaded, then the Where to start table.

Ranking

Sites are ranked by out-of-hours use above base load, in £ a year. That's energy used when the building should be closed, over and above what never switches off. It's usually the cheapest saving to get (time controls, BMS schedules), which makes it a good first sort. Ties go to the site with the bigger bill.

Sorting and exporting

Click any heading to sort. Text columns sort A to Z first, number columns largest first; click again to reverse. Data sorts Good, Check, Poor; Findings sorts by the most High findings. Click # to go back to the ranking. Table to Excel saves the table as a one-sheet spreadsheet in the order shown, so sort first. It holds no half-hourly data, so it's fine to send to a client.

7. Findings

Each site page lists what stands out, most important first. A finding is High when it costs 10% or more of the site's annual bill, Medium at 4% or more, and Low below that, so a £2,000 issue matters more at a small site than a big one. Some findings have a fixed level (see the table).

How to use the £ figures

They're what each pattern costs now, at the rate entered. They overlap (weekend running is part of the out-of-hours figure), so don't add findings together. For a savings estimate, take the out-of-hours figure and apply your own judgement about how much is controllable.

8. Data quality check

Every file is checked for the problems that most often distort HH analysis. Each problem says how it affects the numbers. The verdict is:

  • Good: nothing found. The figures can be relied on.
  • Check: usable, but read the flagged items first.
  • Poor: at least one problem big enough to distort the figures. Fix or replace the data before using them.
CheckWhat it looks forCheck / Fail
CoverageDays of data. Annual figures are scaled up from what's there.Check under 330 days; Fail under 180
Missing daysDays missing between the first and last date.Fail if over 10% of the period
Zero daysWhole days with (almost) no use: usually missing data recorded as zero.Fail if over 3% of days
DropoutsReadings of exactly zero for 2 hours or more inside an otherwise normal day.Fail if over 5% of days
Negative readingsExport from on-site generation, a reversed CT, or a sign error.Always Fail
Stuck readingsThe same non-zero value for 6 hours or more: usually estimated or profiled data.Fail if over 10% of days
Copied daysA day identical to an earlier one. Real metering never repeats exactly; these are estimates.Fail if over 5% of days
SpikesReadings over 3 times the normal peak (99.5th percentile) and at least 5 kW above it.Check only

Stuck readings can be normal on a small site whose meter records whole kWh only. Ignore that check if so.

Why this matters

Zero days and dropouts pull base load and annual totals down. Estimated data hides how the site really ran. A single spike sets the peak demand figure and the headroom answer. Check the verdict before quoting peak, capacity or savings.

9. Electrification headroom

Enter the agreed supply capacity (kVA) on a site to see how much load (heat pumps, EV charging, new plant) it can add before it outgrows the supply.

The figures

  • Usable capacity: agreed capacity less a safety margin (10% by default, changeable), held back for start-up currents and a colder winter than the one in the data.
  • Peak demand (kVA): the highest half-hour in the data, as kW divided by power factor.
  • Firm headroom (kW): (usable kVA minus peak kVA) times power factor. The load you could add at any time of year and stay within usable capacity.
  • Peak by month shows the seasonal shape. Highest demand at each time of day shows the worst case in each half hour, for the whole year and for December to February, which is usually the pinch.

Test a new load

Enter a load in kW, the hours it runs and whether it runs all year or October to April. The app adds it to every half hour it would run in and reports whether it fits, how often and by how much it wouldn't, and when the worst clash is.

  • Heat pumps: enter the electrical input, not the heat output. A 150 kW (heat) unit at a COP of 3 draws about 50 kW.
  • Overnight EV charging: e.g. 22:00 until 06:00. Hours that wrap past midnight are fine. The same start and end means all day.
  • A load that doesn't fit at the worst time may still fit with controls that hold it off at peak. The time-of-day chart shows where the room is.
Limits

This uses one year's peak from one meter. It doesn't know about a colder year, load on other meters on the same supply, or DNO constraints upstream. It's a screen to decide whether a capacity conversation is needed, not a substitute for one.

12. Customer editions

A customer edition is a single HTML file holding one client's sites, locked with a password. The client opens it in their browser, explores their own data and downloads their own reports, without getting the raw data or being able to change the set-up.

Making one

  1. Load only that client's sites, set them up fully, and add the client name and logo.
  2. Click Customer edition… on the main page. Check the customer name and year; the password fills in.
  3. Click Create file. It saves to Downloads as client-name-energy-dashboard.html.
  4. Open it yourself with the password and check it before sending.
  5. Send the file and the password separately: file by email, password by phone or text.

The password

The standard password is the customer name in lower case, letters and digits only, followed by the year it was made. For example, Compleat Foods in 2026 is compleatfoods2026. You can type a different one in the dialog.

The standard pattern is guessable

Anyone who knows the convention, or has seen this guide, can work out a client's password. That's fine for low-sensitivity data. For anything sensitive, or larger public sector estates, add a random part (e.g. compleatfoods2026-tulip84) and keep a note of it. Never send the password in the same email as the file.

Security and limits

  • The data is compressed and encrypted with AES-256-GCM, with the key derived from the password (PBKDF2-SHA-256, 310,000 rounds). Without the password the file holds nothing readable.
  • The password protects the file, not what an authorised viewer sees: anyone who opens it can read the numbers on screen.
  • An edition is a snapshot. It can't be updated or withdrawn once sent. To refresh it, make and send a new one.
  • A forgotten password can't be recovered. Make a new edition.

13. Calculation reference

FigureHow it's worked out
Demand (kW)Half-hourly kWh × 2.
Annual kWh and costTotal kWh in the file × 365.25 ÷ days of data. Cost = annual kWh × unit rate. Missing periods are assumed to look like the ones present.
Base load (kW)The 5th percentile of all half-hourly demand, not the minimum, so a single dropout or zero reading doesn't set it. Blank readings are left out.
Base load costBase kW × 8,766 hours × rate.
Out-of-hours useAll kWh in half hours outside opening hours, scaled to a year.
Out-of-hours above baseFor each out-of-hours half hour, demand above base load (never below zero), scaled to a year and priced. This is the ranking figure.
Peak and load factorPeak is the highest half hour (× 2 for kW). Load factor = average kW ÷ peak kW.
Finding level£ a year ÷ annual bill: 10% or more High, 4% or more Medium, below that Low.
Weekend runningMedian weekend day ÷ median weekday. Reported at 50%, High at 70%.
Bank holidaysHolidays using 80% or more of the median weekday, at sites that close on them.
Base load creep5th percentile base for each month with 20+ days of data. Months paired with the same month a year later; reported if the average rises 15% or more over at least two pairs. Cost = increase × 8,766 × rate.
Unusual daysEach day's kWh against the median for its kind (weekday, Saturday, Sunday; bank holidays counted as Sundays). Flagged if more than 4 robust standard deviations (1.4826 × median absolute deviation) away and at least 25% off the median.
Peak kVAPeak kW ÷ power factor (0.95 default).
Usable capacityAgreed kVA × (1 − safety margin). Margin 10% by default.
Firm headroom(Usable kVA − peak kVA) × power factor, in kW.
Test loadLoad kW ÷ power factor added to each half hour in its time window and season (all year, or October to April). Any half hour over usable kVA counts as a clash.
Day and nightNight 00:00 to 07:00 by default, adjustable on the chart.

The app's maths is tested against the Python version of the same analysis on reference files, so both give the same answers.

14. Limits and troubleshooting

Known limits

  • One flat rate. No time-of-use bands, capacity charges or reactive power charges.
  • Clock changes. Each day is treated as 48 half hours. On a 50-period export the two extra clock-change periods are dropped; on a 46-period day the last hour is blank. The effect on annual figures is negligible.
  • Bank holidays are England and Wales only.
  • School holidays aren't built in; they count as out of hours, which is usually what you want.
  • Large files. Several years of data or 100+ sites will work but take longer. Load in batches if the browser struggles.
  • Nothing is saved between sessions. Closing the tab clears everything. Export what you need first.
